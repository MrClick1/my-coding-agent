# SafePatch Agent

一个用于学习编程 Agent 底层机制的轻量项目。当前已经完成持续聊天、模型流式输出、工具进度事件、文件浏览、代码搜索、受控文件创建/删除、精确文本修改、批量变更事务、修改预览与人工确认、会话修改日志、安全回滚、修改后测试验证和可复现基准测试，而不是一开始堆叠复杂框架。

代码参考 `agent-tutorial` 等项目的学习思路，但采用独立结构重新实现。

## 当前阶段：支持受控单项与批量事务的 Coding Agent

当前版本已经打通：

```text
持续聊天或一次性自然语言任务
    -> OpenAI 兼容模型（默认使用有界 SSE 流式响应）
    -> 实时输出文本增量，并重组工具名称与 JSON 参数增量
    -> 工具调用（Tool Calling）
    -> list_files / search_code / read_file
    -> create_file / replace_text / delete_file / apply_change_set / run_tests
    -> AgentState 记录读取、修改与测试状态
    -> replace_text 展示完整 unified diff 并等待用户确认
    -> create_file 展示完整新增 diff，并以排他方式发布完整文件
    -> delete_file 展示完整删除 diff，经隔离复核后删除文件
    -> apply_change_set 汇总多文件 diff，一次批准并在失败时恢复已应用项
    -> ChangeJournal 记录路径、正向 diff、前后 SHA-256 与测试状态
    -> 未验证修改会阻止最终回答
    -> 工具结果回传模型
    -> 最终回答
    -> 保留有界的用户目标与最终回答历史
    -> /changes 查看会话修改；/rollback 校验并预览反向 diff 后回滚
    -> [模型] / [工具] / [验证] 终端进度事件
    -> 隔离 fixture 自动评分与 JSON 报告
```

运行时还会强制执行十一项约束：

- 工具只能访问指定工作区，拒绝绝对路径和 `../` 路径越界；
- `.env`、`.git`、私钥和常见凭据文件会被隐藏并拒绝读取；
- 模型调用轮数和工具调用总数都有上限，避免 Agent 无限循环或单轮滥用工具；
- 修改已有文件前，目标必须在当前任务中通过 `read_file` 成功读取；
- 每次精确替换都必须向终端用户展示完整 diff 并获得明确批准；
- 新文件只能创建在已经存在的安全父目录中，目标必须不存在、内容必须为非空 UTF-8 文本，并在完整预览和批准后排他写入；删除文件前也必须先读取目标、完整预览并明确批准；
- 批量变更限制为 1 到 20 个不同路径，所有替换和删除目标仍需先读，整批 diff 必须完整可展示，并且只在全部预检通过后请求一次确认；
- 最新一批修改必须调用 `run_tests`，否则 Agent 不能给出最终回答；
- 只有成功写入的修改才会进入日志，日志容量不足时会在写入和确认前拒绝修改；
- 回滚前必须确认文件仍与 Agent 写入后的版本完全一致，并再次展示反向 diff、获得用户批准；回滚结果也必须重新测试；
- 流式响应有 5 MB 累计上限，只有在文本、工具调用编号、名称、类型和完整 JSON 参数全部重组校验后，Agent 才会执行工具。

当前提供三种受控文件变更方式。`replace_text` 不会在缺少旧内容校验时直接覆盖整个文件：旧文本的实际出现次数必须与预期完全一致，修改后的文件不能超过 1 MB，完整预览不能超过 3 万字符。用户批准后还会重新读取文件；如果文件在确认期间发生变化，写入会被取消。最终修改通过同目录临时文件进行原子替换。

`create_file` 只接受新文件的完整非空 UTF-8 内容，不会创建父目录，也不能覆盖普通文件、目录、符号链接或并发出现的目标。完整内容必须能在 3 万字符预览上限内展示；批准后先把内容写入并同步到同目录临时文件，再用不会覆盖现有目标的排他硬链接发布。即使其他进程在最后时刻抢先创建同名文件，Agent 的创建也会失败并保留外部文件。

`delete_file` 只删除已经通过 `read_file` 读取的安全 UTF-8 文本文件。删除前会展示从现有文件到 `/dev/null` 的完整 diff；批准后再次校验正文和字节数，再把目标原子移入同目录隔离文件。只有隔离内容仍与预览版本完全一致时才最终删除；最后时刻出现竞态时会恢复隔离文件，不会静默删除新内容。删除同样受 1 MB 文件读取上限和 3 万字符完整预览上限约束。项目仍不提供任意 Shell。

`apply_change_set` 用于一次提交多个不同路径上的 `create`、`replace` 和 `delete`。它先校验全部参数、路径、原始正文、替换次数、日志容量和合并后的完整 diff，再向用户请求一次确认；确认后重新检查每个路径才按清单应用。如果某一项失败，运行时会反向恢复本批次已经成功应用的创建、替换或删除。这里的“事务”是进程内的失败恢复机制，不是跨进程崩溃后仍能自动恢复的文件系统事务；突然断电或进程被强制终止时仍应依赖 Git 或备份。

持续聊天会在内存中保存最多 100 条修改及最多 20 MB 的回滚正文。每条记录包含变更类型、修改编号、相对路径、前后 SHA-256、完整正向 diff、替换次数和最近一次固定测试结果。创建记录会明确标记创建前文件不存在，删除记录会明确标记删除后文件不存在。日志不会读取或记录 `.env` 等被禁止的敏感文件，也不会被发送给模型作为聊天历史。退出进程后日志会消失，因此它是会话级安全网，不是 Git 或持久备份的替代品。

`/rollback` 默认撤销最近一条仍然活动的修改，也可以指定编号或使用 `all`。同一文件有连续修改时会按从新到旧的顺序校验和恢复；回滚创建记录时会明确说明文件将被删除，回滚删除记录时会展示完整新增 diff 并排他恢复原文件。若路径状态已被用户、其他进程或后续修改改变，回滚会在展示确认前停止，不会删除或覆盖外部新内容。连续的“创建后删除”等净状态不变的记录可以一起回滚而不产生多余文件写入。多文件回滚若在写入、创建或删除中途失败，会尽力恢复本次已经变更的文件，并且只有全部成功后才更新日志状态。

这些规则是教学项目中的防护层，不等同于操作系统级沙箱。敏感文件名拒绝表也不可能覆盖所有凭据格式，因此不要把包含真实生产密钥的不可信目录直接交给模型。

## 当前可用工具

- `list_files`：列出安全相对目录下的文件和目录；
- `search_code`：在安全相对路径下递归搜索字面量，返回文件路径、行号、列号和命中内容；
- `read_file`：按行读取工作区内的 UTF-8 文本文件；
- `create_file`：完整预览并人工确认后，排他创建新的非空 UTF-8 文件；
- `replace_text`：预览并人工确认对已读取文件的精确字面量替换；
- `delete_file`：读取目标后，完整预览、人工确认并隔离复核后删除 UTF-8 文件；
- `apply_change_set`：汇总预览并统一批准最多 20 个不同文件的创建、精确替换和删除，失败时恢复本批次已应用项；
- `run_tests`：在工作区执行固定的 `python -m pytest -q`，不接受模型提供的命令参数。

`search_code` 默认不区分大小写，可以限定单个文件或目录；默认最多返回 50 条结果，可在 1 到 100 之间设置。文件工具都会遵守工作区边界与敏感文件过滤，并分别设置结果数、扫描量、读取量或输出大小上限。

`run_tests` 使用当前 Python 环境，固定 120 秒超时和 4 万字符输出上限，并移除常见密钥变量、`PYTHONPATH` 和 pytest 注入变量。测试通过或失败都会被记录；如果测试失败，Agent 可以如实报告失败，但不能声称任务验证成功。测试本身会执行项目中的 Python 代码，这不是操作系统级沙箱，因此只应对你信任的工作区启用。

## 准备环境

项目使用 uv 管理 Python 3.12、虚拟环境和依赖。首次进入项目后执行：

```powershell
uv sync
```

uv 会根据 `.python-version` 和 `uv.lock` 创建 `.venv`，并安装项目及开发依赖。

复制配置模板并填写你所使用的 OpenAI 兼容服务：

```powershell
Copy-Item .env.example .env
```

```dotenv
LLM_API_KEY=your-key
LLM_BASE_URL=https://your-provider.example/v1
LLM_MODEL=your-model
LLM_TIMEOUT_SECONDS=60
```

`.env` 不会被 Git 提交；同名系统环境变量的优先级高于 `.env`。
远程 API 地址必须使用 HTTPS；只有 `localhost` 和回环 IP 地址可以使用 HTTP，方便连接本地模型服务。

## 运行

不提供位置任务参数时，会启动持续聊天：

```powershell
uv run safe-patch-agent --workspace .
```

CLI 默认请求 SSE 流式响应。模型文本会边生成边显示，工具执行时只显示工具名称、成功状态和耗时，不会把工具结果正文或文件内容额外输出到进度日志。例如：

```text
[模型] 第 1 轮生成中...
[工具] 开始 search_code
[工具] 完成 search_code（成功，0.004 秒）
[模型] 第 2 轮生成中...

Agent> 找到了目标定义……
```

如果某个 OpenAI 兼容服务不支持 Chat Completions SSE，可以切回原有同步响应；工具进度仍会显示：

```powershell
uv run safe-patch-agent --workspace . --no-stream
```

流式模式会按工具调用 `index` 分别累积可能被拆散的调用 ID、函数名和参数，直到收到结束原因并成功解析完整 JSON 后才交给 Agent。中途断流、非法 UTF-8、非法 JSON、不连续的工具编号或超出响应上限都会停止本轮，不会执行不完整工具调用。库级 `CodingAgent.run()` 和基准运行器仍默认使用同步模式，只有显式传入 `stream=True` 才启用流式客户端，保证现有嵌入代码兼容。

会话中可以连续输入自然语言任务，也可以使用：

- `/help`：显示会话命令；
- `/changes`：查看当前会话的修改编号、路径、前后哈希和测试状态；
- `/rollback`：预览并回滚最近一次活动修改；
- `/rollback 3`：回滚编号为 3 的修改；如果同一文件上还有更新修改，会安全拒绝并要求先撤销更新项；
- `/rollback all`：按从新到旧的顺序回滚当前会话全部活动修改；
- `/clear`：清除对话历史；修改日志和待验证修改不会被清除；
- `/exit`：退出会话。

会话默认保留最近 20 轮“用户目标 + 最终回答”，并限制为 8 万字符。旧工具输出不会永久加入历史，避免上下文无限增长；如果后续任务依赖文件内容，Agent 仍需重新使用工具检查。每一轮都会重置已读文件和当轮测试结果，上一轮读过文件不能绕过下一轮的先读后写规则。如果上一轮已经写入但在测试前异常结束，待验证修改会跨轮保留，下一轮仍不能绕过测试门禁。`/clear` 只清除聊天上下文，不会清除修改日志或待测试状态。聊天历史和修改日志目前都只保存在当前进程内存中，退出会话后不会持久化。

仍然可以提供任务参数，执行完成后立即退出：

```powershell
uv run safe-patch-agent --workspace . "请总结这个项目的结构和入口"
```

也可以先执行一个初始任务，然后继续聊天：

```powershell
uv run safe-patch-agent --workspace . "请先总结项目" --chat
```

也可以使用模块入口：

```powershell
uv run python -m safe_patch_agent --workspace . "README 说明了什么？"
```

也可以让 Agent 先搜索符号，再阅读相关文件：

```powershell
uv run safe-patch-agent --workspace . "请搜索 AgentError 的定义和引用，并说明错误处理流程"
```

修改任务会强制执行“先读后写”，例如：

```powershell
uv run safe-patch-agent --workspace . "把 README 中的当前阶段标题改为更准确的描述"
```

Agent 必须先调用 `read_file`，随后才能调用 `replace_text`。如果旧文本出现次数与预期不一致，工具会拒绝修改并要求模型重新检查文件。替换通过校验后，CLI 会展示完整 unified diff，并询问 `应用以上修改？[y/N]`；只有输入 `y`、`yes` 或 `是` 才会写入，直接回车和其他输入都会拒绝。非交互式输入不能批准修改。修改成功后还必须调用 `run_tests`，否则主循环会要求模型继续验证，不能直接结束任务。

创建新文件不要求读取尚不存在的目标，例如：

```powershell
uv run safe-patch-agent --workspace . "创建 src/example.py，提供一个 add 函数及类型注解"
```

Agent 会调用 `create_file` 提交完整内容。CLI 展示新增文件的完整 diff 并询问 `创建以上文件？[y/N]`；明确批准后才会排他创建。创建成功与修改已有文件一样必须运行固定测试，也会进入 `/changes` 和 `/rollback`。`/rollback` 创建记录会再次展示完整删除 diff，并明确列出将删除的会话创建文件。

删除现有文件必须先读取完整目标，例如：

```powershell
uv run safe-patch-agent --workspace . "确认 src/obsolete.py 已无用途后删除它"
```

Agent 必须先调用 `read_file`，随后才能调用 `delete_file`。CLI 会展示完整删除 diff 并询问 `删除以上文件？[y/N]`；批准后仍会执行并发复核。删除成功后必须运行固定测试，并会在 `/changes` 中显示删除后哈希为“（不存在）”。`/rollback` 删除记录会明确列出将恢复的文件，并在目标仍然不存在时排他恢复原内容。

多个不同文件需要协同变更时，可以要求 Agent 使用一次批量事务：

```powershell
uv run safe-patch-agent --workspace . "读取相关文件后，批量创建配置、更新入口并删除旧模块"
```

Agent 会先分别读取所有 `replace` 和 `delete` 目标，再调用 `apply_change_set` 提交操作数组；`create` 项提供完整 `content`，`replace` 项提供 `old_text`、`new_text` 和可选的 `expected_replacements`，`delete` 项只提供路径。CLI 汇总文件数、三类操作数量、总字节变化和全部 unified diff，并只询问一次 `应用以上批量变更？[y/N]`。批次成功后，每个操作仍作为独立记录出现在 `/changes` 中，因此可以继续使用现有 `/rollback` 机制精确撤销。

## 基准测试

仓库自带三个小型案例，分别检查文件读取、符号搜索和“修复代码后运行测试”。每个案例的 fixture 都会先复制到新的临时目录，因此模型的修改不会污染版本化样本。评分器会同时检查：

- Agent 是否正常结束；
- 最终回答是否包含必要信息；
- 模型是否成功调用了指定工具；
- 修改后的目标文件是否与预期精确一致；
- 需要测试的案例是否实际运行且通过测试。

使用已配置的真实模型运行全部案例：

```powershell
uv run safe-patch-benchmark
```

这条命令会产生真实模型 API 调用，可能产生费用，所以普通离线测试不会自动执行它。基准 fixture 是用完即删除的隔离副本，因此基准运行器会显式自动批准其中的单项或批量文件变更，不会弹出人工确认。运行结果会显示逐案例成败和整体成功率，完整 JSON 默认写入 `benchmark-results/latest.json`；该目录已被 Git 忽略。案例格式位于 `benchmarks/cases.json`，可以通过 `--manifest` 和 `--output` 指定其他清单与报告路径。

测试使用假的模型客户端，不会发起网络请求，也不需要 API 密钥：

uv run pytest

5. **已完成：修改后测试**——加入固定的 `run_tests`，未验证修改会阻止最终回答；
6. **已完成：小型基准测试**——隔离运行版本化 fixture，自动检查回答、工具轨迹、文件结果和测试状态，并输出成功率报告；
7. **已完成：修改预览与人工确认**——写入前展示完整 diff，默认拒绝，并防止确认期间的并发变更被覆盖；
